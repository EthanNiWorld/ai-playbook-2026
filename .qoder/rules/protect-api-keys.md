# API Key 防泄漏规则

## 核心约束

**禁止将包含 API Key、密钥、Token 等敏感信息的文件提交到 Git。**

## 详细说明

1. **禁止提交含密钥的文件**：在执行 `git add`、`git commit`、`git push` 之前，必须检查目标文件中是否包含以下模式的敏感信息：
   - API Key（如 `sk-xxx`、`ak-xxx`、`key-xxx`）
   - 密钥/密码（如 `password`、`secret`、`token`、`api_key` 后跟具体值）
   - 数据库连接串
   - 任何硬编码的凭证

2. **必须先扫描再提交**：执行 git 操作前，应对 staged 文件进行密钥扫描。如果发现敏感信息：
   - 立即阻止提交操作
   - 告知用户哪些文件包含敏感信息
   - 建议将敏感信息移至环境变量或 `.env` 文件

3. **测试脚本中的密钥**：如果测试脚本中硬编码了 API Key 用于调试，提交前必须：
   - 将密钥替换为环境变量读取（如 `os.getenv("DASHSCOPE_API_KEY")`）
   - 或将该文件加入 `.gitignore`

4. **禁止硬编码，必须时须确认**：在编写或修改代码时：
   - **默认使用环境变量**读取密钥，不得直接写死在代码中
   - **禁止硬编码绝对路径**（如 `/Users/xxx/project`），应使用 `os.path.dirname(__file__)` 或相对路径动态推导，确保代码可移植
   - 如果用户明确要求硬编码（如快速调试），必须**先向用户确认风险**并告知：
     - 该文件不应提交到 Git
     - 建议加入 `.gitignore`
     - 调试完成后应改回环境变量/相对路径方式
   - 绝不在未经确认的情况下将用户提供的密钥值写入代码文件

5. **允许的操作**：
   - 提交不含敏感信息的代码和配置
   - 在代码中引用环境变量（如 `os.environ.get("API_KEY")`）
   - 提交 `.env.example`（仅含占位符，不含真实密钥）
