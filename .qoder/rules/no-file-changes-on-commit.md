# 提交 Git 时禁止新建或编辑文件规则

## 核心约束

**在执行 git 提交相关操作（add / commit / push）的整个过程中，禁止新建或编辑任何文件。**

## 详细说明

1. **提交前锁定文件状态**：从决定执行 `git add` / `git commit` / `git push` 的那一刻起，到操作全部完成为止，不得进行任何文件写入操作，包括但不限于：
   - 新建文档（README、CHANGELOG、总结报告、执行日志等）
   - 修改任何已有文件的内容（即使发现"顺手就能改"的小问题）
   - 重命名、移动文件
   - 生成临时文件、截图、构建产物到仓库目录内

2. **发现问题时的正确做法**：
   - 提交过程中发现文件有错误或缺失内容 → **先中止提交流程**，向用户报告问题
   - 用户确认需要修复 → 修复完成后**重新走确认流程**，再执行提交
   - 禁止"边改边提交"，禁止把修复与提交混在一次操作中

3. **提交内容必须与用户确认过的一致**：
   - `git add` 的范围只能是用户知晓并同意的变更
   - 提交流程中 Agent 自行产生的任何新文件（日志、报告、笔记等）一律不得加入本次提交

4. **允许的操作**（不视为新建/编辑文件）：
   - 只读操作：`git status`、`git diff`、`git log`、读取文件内容
   - 提交本身：`git add`、`git commit`、`git push`（针对已存在且已确认的变更）
   - 在 `/tmp/` 等仓库外目录的临时产物

## 背景与解决的问题

> **为什么需要这条规则**：Agent 在执行提交时，容易在提交流程中"顺手"生成执行日志、总结文档，
> 或发现小问题后直接修改再一并 add，导致用户确认的提交范围与实际提交内容不一致，
> 污染提交历史，且未经用户审核的内容被推送到公开 GitHub 仓库。
> **解决什么问题**：将"文件变更"与"提交操作"两个阶段强制隔离，
> 确保提交内容严格等于用户确认过的变更集合，Agent 不得在提交窗口内追加任何文件改动。
