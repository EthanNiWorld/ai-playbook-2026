# 用户隐私信息保护规则

## 核心约束

**禁止将用户对话中出现的隐私信息写入任何文件，尤其是可能被开源或提交到 Git 的文件。**

## 禁止写入的内容

1. 用户提供的具体文件名（如 `yandorr.chm` → 替换为 `example.chm`）
2. API Key / Token / Secret（如 `sk-xxx`、`ak-xxx`）
3. 图片/截图中可见的个人信息（人名、手机号、身份证、地址、照片内容描述）
4. 用户本地路径（如 `/Users/xxx/...`）
5. 截图中的账号、密码、邮箱
6. 对话上下文中提到的任何隐私数据

## 执行时机

- **每次写入或修改文件前**，必须扫描即将写入的内容
- 如果发现疑似隐私信息，**必须先向用户确认**再决定是否写入
- 对于开源项目文件（README、LICENSE、公开代码），执行更严格的脱敏标准

## 替代策略

- 文件名 → 使用 `example.xxx` / `sample.xxx`
- API Key → 使用 `YOUR_API_KEY` 占位符
- 路径 → 使用相对路径或 `/path/to/`
- 人名/账号 → 使用 `user@example.com` 等通用格式

## 允许的操作

- 在对话中讨论隐私信息（不写入文件）
- 用户明确确认后写入特定信息（需告知风险）
- 写入已脱敏的占位符内容
