🎯 五大省钱技巧
Tip 1 · 预计节省 50-65%

智能问答（Ask）优先：能问就别让 AI 动手

智能问答/Ask 模式（~3-4 Credits）只做问答和代码阅读，Agent 模式（~7-12 Credits）会读写文件、执行命令。很多场景智能问答就够了。

场景 用智能问答（3-4 Credits） 用 Agent（7-12 Credits）
理解一段老代码 ✅ "这段代码的逻辑是什么？" ❌ 杀鸡用牛刀
Debug 定位问题 ✅ "这个报错可能是什么原因？" ⚠️ 需要直接改文件时才用
方案选型讨论 ✅ "Redis 和 Memcached 怎么选？" ❌ 纯讨论不需要文件操作
写一个新功能 ❌ 智能问答无法写文件 ✅ 需要创建/修改文件
Code Review ✅ 选中代码 + "帮我 review" ⚠️ 要批量修改时才用
黄金法则：先用智能问答问清楚方案，想明白再切 Agent 动手。避免 Agent 模式下反复试错——每次试错都是 7-12 Credits。
Qoder 界面：在对话顶部切换「智能问答 / Ask」与「Agent」模式
Tip 2 · 预计节省 30-50%

会话隔离：换任务就开新窗口

多轮对话会累积上下文，上下文越大，每次请求的 Credits 消耗越高。50K 窗口 vs 200K 窗口，Agent 模式消耗差近 1.7 倍。

❌ 错误做法
~12 Credits/次
同一个窗口做完需求 A，接着做需求 B
200K 上下文，前一个任务的代码全在历史里
→
✅ 正确做法
~7 Credits/次
需求 B 开新窗口
50K 上下文，干净环境
什么时候该开新窗口？
• 切换到完全不同的功能模块
• 当前对话超过 15-20 轮且新任务与之前无关
• 发现 AI 的回答开始"串"之前任务的内容
什么时候保留同一个窗口？
• 同一个功能的迭代（修 Bug → 加测试 → 优化），需要上下文延续
• 复杂重构，AI 需要理解你之前做的改动
Qoder 界面：通过「新建会话」开新窗口，避免上下文膨胀
Tip 3 · 预计节省 40-60%

模型分级调度：把贵模型用在刀刃上

Qoder 支持全球 SOTA + 亚太 SOTA 模型，可在对话界面自由切换模型。核心思路：规划和设计用最聪明的模型，执行和测试用性价比模型。

开发阶段 推荐模型 推荐模式 原因
Spec / Plan 设计 极致模型 / 其他 SOTA 模型 智能问答 架构决策不可逆，需要最强推理；设计文档不需要改文件
代码实现 DeepSeek-V4 / GLM-5.2 / Qwen 3.7-Max Agent 编码能力接近旗舰，价格大幅降低
日常 Debug Qwen 3.7-Plus 智能问答 问答式排查，不需要文件操作
测试生成 / 格式化 Qwen 3.7-Plus Agent 模板化工作无需高端模型
实操建议：一个功能的开发全流程——先用智能问答 + 极致模型讨论 Spec/Plan（3-4 Credits × 2-3 轮），然后切到 DeepSeek/GLM/Qwen 3.7-Max 用 Agent 模式逐步实现（7-12 Credits × 实现轮次），最后用智能问答做 Review（3-4 Credits × 1-2 轮）。比全程旗舰模型省 50%+。
Qoder 界面：在对话中自由切换模型（极致模型、DeepSeek、GLM、Qwen 等）
Tip 4 · 预计节省 20-30%

精准引用文件：别让 AI 自己找

AI 搜索文件、阅读文件都会扩大上下文窗口，直接增加消耗。主动提供精确上下文，比让 AI 自己去"探索"省很多。

❌ 模糊指令
"帮我把用户认证那块改一下"

→ AI 搜索 5-10 个文件
→ 读取 3-4 个相关文件
→ 上下文膨胀到 200K+
→ 每次后续请求 12 Credits
→
✅ 精准指令
"修改 src/auth/jwt.ts 的
validateToken 函数，增加过期检查"

→ AI 直接定位 1 个文件
→ 上下文保持 50K
→ 每次后续请求 7 Credits
  • 在 Chat 中 @ 具体文件，而不是描述"那个文件"
  • 选中代码片段再提问，AI 只需处理你选中的部分
  • 用 .qoder/rules/ 目录存放项目规范，AI 自动遵守，减少反复修改
Tip 5 · 一劳永逸

Rules + Memory：让 AI 记住你的习惯

每次都要重复告诉 AI "用 TypeScript"、"用 pnpm"、"变量名用 camelCase"？把这些写成 Rules，AI 每次自动遵循，不需要在对话中反复说明。

# .qoder/rules/coding-style.md 示例 ## 代码规范 - 语言：TypeScript，严格模式 - 包管理：pnpm（不要用 npm/yarn） - 变量命名：camelCase，接口用 PascalCase - 注释语言：中文 - 测试框架：vitest ## 项目约定 - API 路由放 src/routes/ 目录 - 数据库操作用 Prisma ORM - 错误处理用自定义 AppError 类
省在哪里？
• 减少无效对话轮次：不需要每次说"用 pnpm"，少 2-3 轮对话 = 省 6-36 Credits
• 减少返工：AI 第一次就按规范写，不用"改成 pnpm"再来一轮
• Memory 自动学习：Qoder 会记住你的偏好，新窗口也生效
