一、问题场景与错误信息

典型错误 1（API 调用 403） httpCode: 403，AccessDenied.Unpurchased
场景：RAM 子账户通过其创建的 API Key 调用 kimi-k2.7-code 模型时触发。
典型错误 2（控制台无权限） "You do not have access permissions to this workspace, or the workspace does not exist"
场景：RAM 子账户登录百炼控制台后看到锁形图标与刷新按钮。

两个错误的根因都指向业务空间授权缺失，解决方案见第二章与第三章。

二、核心操作流程（6 步搞定）

场景说明 以阿里云国际站（主账号）为例，为三方模型 kimi-k2.7-code 配置 RAM 子账户调用权限。所用控制台为国际站百炼（bailian.console.alibabacloud.com/cn-beijing，华北2 北京节点）。完整概念与字段说明见官方文档《百炼权限管理》。

1主账号创建 RAM 用户

主账号登录 RAM 控制台 → 身份管理 → 用户 → 创建用户。

用户名称示例：kimi-k2.7-code_RAM-Test（最多 64 字符，支持英文、数字、下划线、连字符、点号）。勾选使用控制台访问。

说明 本指南仅针对百炼 API-Key调用场景。AccessKey ID / Secret 仅在需要同时调用其他阿里云 OpenAPI 时才需创建，两者账号体系与控制台不同，详见官方文档。

2为 RAM 用户授予超级管理员策略

在 RAM 控制台为目标用户新增授权，搜索并勾选以下策略：

权限策略说明是否必须
AliyunBailianFullAccess 百炼平台超级管理员，可跨业务空间管理 ✅ 必须
AliyunBSSOrderAccess 购买预付费模型时使用 ⚠️ 按需

3主账号 RAM 登录设置

返回 RAM 用户详情 → 认证管理 → 启用控制台登录：

RAM 控制台 → 用户 → kimi-k2.7-code_RAM-Test → 认证管理 → 启用控制台登录

4主账号创建业务空间并授权 kimi 模型

主账号访问 百炼控制台（业务空间管理），点击新增业务空间，输入名称 kimi-k2.7-workspace，地域默认华北2（北京）。

无隔离需求？ 可跳过本步骤直接使用 Default 业务空间，其内置所有模型授权。最多创建 20 个业务空间。

4.1 授权 kimi-k2.7-code 模型调用

进入 kimi-k2.7-workspace → 模型列表 → 搜索 kimi，找到 kimi-k2.7-code → 打开模型调用开关 → 保存。

5在业务空间内添加 RAM 用户

在 kimi-k2.7-workspace → 账号管理 → 新增用户：

填写要点：

  • 类型：RAM 用户
  • RAM 用户：下拉选择 kimi-k2.7-code_RAM-Test@<主账号 UID>.onaliyun.com
  • 显示名称：kimi-ram-user

新增后在编辑权限中勾选该 RAM 用户可访问的业务空间、页面与API 权限。

关键点 仅"加入空间"不包含任何模型权限，调用模型必须单独勾选模型授权（已在第 4 步开启）。

6RAM 账户登录后创建 API-Key

RAM 用户登录百炼控制台（地域 cn-beijing）→ API-Key → 创建 API Key：

确定后弹出保存 API Key对话框：

⚠️ 不可逆加密 离开此对话框后，将无法再次界面查询 Key 的明文。请立刻复制或点击下载保存。

保存后即可以该 Key 调用 kimi-k2.7-code 模型。端点示例：

API Key：sk-ws-*************.*************************（脱敏示例）
API Host：ws-sy**********.cn-beijing.maas.aliyuncs.com
OpenAI 兼容：https://ws-sy**********.cn-beijing.maas.aliyuncs.com/compatible-mode/v1

三、可能遇到的问题与解决方案

问题 1：RAM 账号登录后看到"无业务空间权限"

根因：该 RAM 用户未被添加到任何业务空间的成员列表。百炼不会自动继承 RAM 用户的任何权限。

解决：主账号在百炼控制台 → 切换到目标业务空间 → 账号管理 → 新增用户 → 选择该 RAM 用户 → 编辑权限勾选业务空间与模型权限。

问题 2：调用模型返回 403 Model access denied

根因：RAM 子账户建的 API Key 所在的那个业务空间，没开通 kimi-k2.7-code 的调用权限。子业务空间默认什么都不授权。

排查思路（两跳走）

①先查这个 API Key 属于哪个业务空间

百炼控制台 → 左侧 API-Key 菜单。问题报的 Key 在这里能看到一行，里面"所归属业务空间"列会直接告诉你这个 Key 归在哪个空间下（例如 kimi-k2.7-workspace）。

②再看这个业务空间有没有授权目标模型

主账号切到该业务空间 → 左侧 模型列表 → 搜索 kimi-k2.7-code → 看"模型调用"列的开关状态：

  • ✅ 已授权 → 说明不是这个问题，继续看 阿里云控制台是否完成该模型的付费开通
  • 未授权 → 打开开关 → 保存即可。实时生效，几秒钟后再调一次

能力超级管理员

A.2 业务空间行为差异

空间类型模型调用授权限流设置模型调优
默认业务空间所有模型默认可调用❌ 不可设置所有支持调优的模型可调优
子业务空间初始无任何模型权限，需手动开启✅ 可设置请求数 / Token 限流初始无权限，需手动开启

A.3 API Key 关键规则

  • 单个 API Key 只能归属一个地域内的一个业务空间，不能转移
  • API Key 的可调用功能 = 归属业务空间的权限（不受用户控制台权限影响）
  • 无需为不同模型创建不同的 API Key
  • RAM 账号被移出业务空间 → API Key 失效；重新加入后恢复
  • RAM 账号在 RAM 控制台被删除 → API Key 永久失效

A.4 常见误区速览

误区正确理解
拥有 AliyunBailianFullAccess 就能调用所有模型该策略仅授予管理操作能力，模型调用权限需在业务空间中单独开启
RAM 用户创建后自动拥有默认空间权限百炼不会自动添加 RAM 用户到任何业务空间，需手动添加
子业务空间和默认空间行为一致子业务空间初始无任何模型权限，必须手动授权
API Key 可以跨空间使用API Key 只能归属一个地域内的一个业务空间，不能转移
不同模型需要不同的 API Key无需为不同模型创建不同的 API Key

A.5 快速 FAQ

Q：如何获取业务空间 ID？
参考 Get the Workspace ID。
Q：权限变更后多久生效？
权限变更实时生效，刷新页面即可。
Q：如何撤销某个用户的权限？
业务空间 → 权限管理 → 删除用户。此操作会同时使该用户在该空间的 API Key 失效。
