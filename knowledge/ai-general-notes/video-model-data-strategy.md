## 是什么

以字节 Seedance 2.0 为样本的视频生成模型数据策略：坐拥全球最大 UGC 视频池（抖音）却几乎不用，转而采买影视级素材，用 LLM 拆解成脚本和分镜作为结构化监督信号；配合上千人数据评测团队和"算法团队内设数据产品经理"的组织形态。行业将 Seedance 2.0 的成功归因为"数据的胜利"（36氪深氪）。

同期配套原则："不做蒸馏"——Seed 从成立之初定下，所有数据靠自己合成、采买、清洗。

## 核心原理

### 1. 数据质量密度决定生成模型上限

- UGC 短视频的特征——手机竖屏、业余运镜、压缩画质、无叙事结构——会作为"缺陷特征"被模型学进去
- 影视素材自带专业灯光、镜头语言、叙事节奏；用 LLM 拆解成脚本和分镜，等于把"导演的决策过程"转为可监督信号（"把一群电影大师放进了模型里"）
- 与 LLM 领域"教科书级语料 > 网页爬虫"是同一条第一性原理，只是视频模态的高质量数据必须花真金白银采买

### 2. 视频模型不蒸馏是必然而非姿态

- **无处可蒸**：视频生成领域没有能力足够强且可访问输出分布的开源老师模型（Veo/Sora 均闭源黑盒）
- **蒸馏的数学天花板**：学生模型逼近老师模型是上界，目标 SOTA 就必须越过所有老师
- "不蒸馏原则"与"数据重投入"是同一个决策的两面：不蒸馏倒逼出庞大的数据组织形态（上千人评测团队、算法-数据接口角色）

### 3. UNet → DiT 是 scaling 收益曲线的切换

- 卷积的局部性归纳偏置在小规模有利、大规模封顶（图像扩散模型视频化路线上限不高）
- DiT 将视频压成时空 token 序列交给 Transformer，去掉手工归纳偏置，换来参数/数据/算力同步放大时效果单调提升的性质
- 大参数下注在 DiT 架构下有确定性回报；稀疏化（MoE）保证推理成本可控

### 4. 视频模型高毛利的技术前提

- 视频生成是计算密集型而非存储带宽密集型任务，可用较便宜的国产芯片跑推理
- 不受高端 GPU 供给约束，规模化时成本可持续摊薄

## 关键认知框架

### 核心洞察 1：质量密度 > 数量

- 模型输出质量的上限由训练数据的质量密度决定，而不是数据量
- 为什么重要：直接推翻"数据越多越好"的朴素直觉，解释了为什么拥有最大数据池的公司反而去外部采买数据
- 可迁移场景：任何生成式模态（音乐、3D、语音）的数据战略评估

### 核心洞察 2：不蒸馏是条件约束下的必然

- 当领域内不存在可访问的开源 SOTA 老师模型时，"自建高质量数据管线"从可选项变成唯一路径
- 为什么重要：数据组织能力（评测团队规模、算法-数据接口角色）本身就是护城河
- 可迁移场景：判断任何"闭源领先、开源缺位"赛道的竞争壁垒构成

### 核心洞察 3：架构选择决定 scaling 下注的确定性

- 技术路线未收敛时，"更快更稳妥"的路线（UNet 视频化）可能上限更低；"更难"的原生路线（DiT）才兑现 Scaling Law
- 可迁移场景：任何新模态的架构选型判断——看归纳偏置是否会封顶 scaling 收益

## 最佳实践

### 可迁移场景（推荐）

- **内容行业**：教材/课程制作中"少量精品示范 > 海量普通样例"的同构逻辑
- **组织设计**：在核心生产环节（算法）与支撑环节（数据）之间设专职"接口人"角色，是高吞吐协作的通用模式

## 常见误区

| 误区 | 事实 |
|------|------|
| 数据越多模型越好 | 质量密度决定上限，UGC 海量数据反而引入缺陷特征 |
| 不蒸馏是道德姿态/公关口径 | 视频赛道无 SOTA 可蒸，是条件约束下的必然选择 |
| 大参数是盲目军备竞赛 | DiT 架构下 scaling 有确定性回报，前提是架构选对 |
| 视频模型和 LLM 一样受 GPU 卡脖子 | 视频推理是计算密集型，国产芯片可跑，供给约束更弱 |
