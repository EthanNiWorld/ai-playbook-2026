PPO vs GRPO vs DPO — 为什么 GLM-5.2 选择 PPO？

长程编程任务（如"花 10 小时优化 CUDA kernel"）的轨迹太长，必须压缩（compaction）。一条超长轨迹变成 N 条子轨迹，不同 rollout 的 N 不同。GRPO 的组内标准化假设"每个 rollout 产生 1 个 reward"彻底崩塌。PPO 的 Critic 可以独立估计每个子轨迹的 token 级 advantage，长度无关。

推理最核心的矛盾：Prefill vs Decode

Prefill（预填充）
✅ 一次处理所有输入 token
✅ 并行计算，GPU 利用率高
✅ 延迟 = O(1) 次前向
⚠️ 计算密集（矩阵乘法）
Decode（解码）
❌ 一次只生成 1 个 token
❌ GPU 大部分时间在等显存
❌ 延迟 = O(N) 次前向
⚠️ 内存密集（读 KV Cache）
瓶颈：假设输入 1000 tokens + 输出 500 tokens，总延迟 ~510ms，Decode 占 98%。而 Decode 阶段 GPU 利用率极低——每次只算 1 个 token 的矩阵乘法，大部分时间在等显存读取 KV Cache。

推理的瓶颈全部在 Decode 阶段 → 对应的优化技术

瓶颈技术代表方案原理
KV Cache 显存爆炸 KV Cache 压缩 MLA IndexShare Lightning 低秩压缩 / 稀疏化 / 线性注意力替代
KV Cache 分级 LayerSplit GPU → CPU → 磁盘三级管理
PagedAttention vLLM 分页管理，不连续分配，减少碎片
Decode 太慢 投机解码 MTP MTP+KVShare 一次预测多个 token
Continuous Batching vLLM 多个请求拼在一起算，提高 GPU 利用率
GPU 利用率低 Prefill-Decode 分离 DistServe / Mooncake Prefill 和 Decode 用不同 GPU
显存不够 量化 INT8 / INT4 / FP8 降低权重精度，显存降低 2-4×

三 推理时计算（Reasoning）：用更多算力换更好质量
推理优化两大方向：
方向 A：系统优化 — 让每一步计算更快、更省（KV Cache 压缩、量化、投机解码、Continuous Batching）。衡量：TTFT、TPOT、吞吐量。
方向 B：推理时计算（Reasoning） — 花更多算力生成更好的答案（Chain-of-Thought、Best-of-N、Verifier、Tree Search）。衡量：准确率、HLE 分数、AIME 分数。

推理时计算的核心公式

答案质量 = f(推理时算力)
├─ Chain-of-Thought：生成更多 token → 更多思考 → 更好的答案
├─ Best-of-N：生成 N 个答案 → 选最好的 → 质量 ↑，成本 ↑ N 倍
├─ Verifier：生成答案 → 验证 → 不对就重试 → 质量 ↑，成本 ↑
└─ Tree Search：分支探索 → 评估 → 选择最优路径 → 质量 ↑↑，成本 ↑↑↑

本质：用推理时的算力换取训练时无法达到的质量。

KV Cache 压缩：三条路线竞合

路线 A：低秩压缩
DeepSeek MLA
把 K/V 投影到低维空间 → 存潜在向量 → 计算时解压
路线 B：线性注意力
MiniMax Lightning
把 O(n²) 变成 O(n) → 不需要 KV Cache
路线 C：稀疏注意力
GLM IndexShare — 只关注最相关的 token → 索引器共享 → 减少计算量

趋势判断：这三条路线不是互斥的，未来可能融合（MLA + 稀疏 + 线性）。

🔑 面试必问三点：
1. PPO vs GRPO vs DPO 的区别和适用场景（为什么 GLM-5.2 选 PPO？为什么 DeepSeek-R1 选 GRPO？）
2. MoE 的 4D 并行（DP × TP × PP × EP）中 EP 的工作原理和 all-to-all 通信挑战
3. Prefill vs Decode 的二元结构，以及围绕 Decode 阶段的三条 KV Cache 优化路线（MLA / 线性注意力 / 稀疏注意力）
⚠️ 高频陷阱：
「DPO 是 RL 算法」— 错！ 本质是分类任务（MLE），不是 RL。
「GRPO 比 PPO 好」— 不一定！ 长程编程 Agent 场景下因轨迹压缩导致组内比较失效。
「推理只关心速度」— 不全面！ 推理时计算（Reasoning）用更多算力换更好质量，与系统优化同等重要。
🚀 一句话总结：
RL 对齐 + MoE 训练 + 推理系统优化 + 推理时计算 是 SA 必须能讲透的四大硬核知识。预训练决定了模型的知识上限，后训练决定了模型的行为下限，推理系统优化决定了服务成本，推理时计算决定了答案质量。四者缺一不可。
