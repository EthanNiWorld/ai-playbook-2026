层决策键职责与理由
开关层租户 UID
（可细到 API Key / 模型级）		回答「要不要检」。合规义务来自租户业务场景（金融/政企面向 C 端），与模型跑在哪无关；计费、审计、自助开关均以 UID 为主键。
执行层渠道（资源1/2/3）回答「在哪检最划算」。默认统一网关侧检测（策略/词库/账单一致）；百炼渠道可选内置护栏降本，但与网关护栏二选一，避免重复检测重复付费。
兜底层全局（可选）平台自身作为生成式 AI 服务提供者的底线合规：全量流量基础检测，租户增强策略叠加其上。
铁律：渠道开关会让合规等级随路由漂移——百炼故障切到自有 GPU 时合规租户瞬间「裸奔」。按 UID 决策与路由完全解耦，任意 failover / 重试 / 渠道套利下合规等级恒定。

网关钩子伪代码（决策与执行分离）
cfg = store.get(tenant_uid)        # 鉴权后 O(1) 查询
if not cfg.enabled: return passthrough(req)
if guard(req.prompt).blocked:     # ❶ 输入同步检测
    return reject(cfg.answer)
stream = route(req)                # ❷ 原有路由/failover 不变
for s in slices(stream, 150):      # ❸ hp 切片, chatId+done
    if guard(s).blocked:
        return revoke_and_replace(cfg.answer)  # ❹
    emit(s)
落地四要点：① 配置中心热更新，开关变更无需重启网关；② 检测状态挂在请求上下文（chatId），渠道重试/failover 不重置、不重复计费；③ 护栏调用设超时（建议 500ms~1s）+ 熔断，故障按租户 fail_policy 处置（合规租户建议 fail-close）；④ 按 UID 计量检测次数（输入 1 次 + 输出 N 切片），透传租户账单或平台补贴。

需要做什么（建设清单）

网关改造围栏插件框架
请求前/响应后钩子 + 租户级开关下发（配置中心热更新），插件故障不拖垮主链路（超时熔断）。
新建输入检测钩子
同步调用 query_security_check，block 直接拒绝并返回代答；实测 TTFT +0.2s，非推理模型需重新评估占比。
新建输出流式检测器
hp 版按字符切片，chatId+done 关联一轮对话；block 立即停发、撤回已透出内容、替换代答。切片粒度可配置（slice_chars，租户级热下发，≤2000 字符/片）：切小→首字早/拦截快但费用高，切大→反之，推荐 100~200 字并按标点边界对齐。
新建租户合规配置中心
租户 → 防护维度/词库/阈值/代答话术/fail 策略的映射；词库变更经配置管理 API 下发（注意 3~5 分钟生效窗口）。
新建计量计费透传
护栏按次计费（双维度 0.003 元/次，流式每切片独立计费）→ 计入租户账单或平台补贴；与网关按 token 计费解耦。
新建监控与配额管理
护栏延迟/错误率/QPS 监控（上限 50/s，每请求消耗 1+N 次配额）；风险事件告警与审计报表对接。
阿里云配置开通与授权
开通 AI 安全护栏（可纯 API 完成，按量后付费不调用不收费）；RAM 用户授予 AliyunYundunGreenWebFullAccess。
阿里云配置词库与代答库
自定义关键词库（竞品词/业务敏感词）绑定到 service；按风险标签配置代答内容；敏感数据脱敏（mask）按需开启。
