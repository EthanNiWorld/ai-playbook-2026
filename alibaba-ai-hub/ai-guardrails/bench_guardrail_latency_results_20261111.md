# AI 安全护栏对 LLM 服务指标影响实测报告（TTFT / 输出速度 / 计费口径）

> 测试日期：2026-11-11 ｜ 脚本：`bench_guardrail_latency.py` ｜ 原始数据：`bench_guardrail_latency_raw.json`
> 链路：glm-5.3（百炼北京，流式）+ AI 安全护栏（北京接入点，外网调用）
> 配套报告：`test_guardrail_custom_keyword_results_20261111.md`（功能拦截验证）

## 一、结论速览

1. **护栏不改变模型本身的生成速度**（completion tok/s 各模式均 83~103，含强制推理），它只影响「内容何时透出给用户」。
2. **输入侧同步检测：TTFT +约 0.2s**（实测 146~356ms/次），代价小，建议标配。
3. **输出侧全量缓冲检测：TTFT 恶化最严重**——首 token 延迟 = 整段生成耗时 + 检测耗时（实测 TTFT 从 14.7s → 20.7s；输出越长越不可接受）。
4. **输出侧流式切片检测（hp 版）：TTFT +约 0.5s，总耗时 +0.3s**，每切片 130~246ms，是体验与安全的推荐平衡点。
5. **费用按「成功 API 调用次数」计，与文本长度无关**（2000 字符内同价）；**流式每个切片 = 1 次独立计费调用**，切片越细费用越高。

## 二、护栏 API 自身延迟（外网 → 北京接入点）

| Service | 样本 | avg | p50 | p90 | max |
| --- | --- | --- | --- | --- | --- |
| query_security_check（输入） | 12 | 185ms | 157ms | 208ms | 356ms |
| response_security_check（输出标准版） | 16 | 213ms | 189ms | 266ms | 460ms |
| response_security_check_hp（输出高性能版） | 22 | 190ms | 186ms | 219ms | 397ms |

- **文本长度几乎不影响延迟**：13 字 vs 1900 字，标准版 avg 210ms → 236ms（2000 字符上限内）。
- hp 版更快更稳（p90 219ms vs 标准版 266ms）；官方宣称的「单切片 <100ms」指服务端处理耗时，外网调用需叠加网络 RTT（本测试环境约 +100~150ms）。网关与护栏同地域 VPC 内网接入可进一步压低。

## 三、四种网关集成模式对照（glm-5.3 流式，每模式 4 次）

固定 prompt：「写一段200字左右的杭州介绍…」，max_tokens=2048。

| 模式 | 集成方式 | TTFT 均值 | ΔTTFT | 总耗时 Δ | 模型生成速度 | 用户可见输出 |
| --- | --- | --- | --- | --- | --- | --- |
| A | 无护栏直连（基线） | 14.70s | — | — | 86~103 tok/s | 逐 token 流畅 |
| B | 仅输入侧同步检测 | 15.59s | +0.89s* | +0.88s | 85~101 tok/s | 逐 token 流畅 |
| C | 输入检测 + 输出**全量缓冲**检测 | 20.68s | **+5.98s** | +5.04s | 87~89 tok/s | 憋到最后一次性吐出 |
| D | 输入检测 + 输出**流式切片**检测（hp，100字/片） | 15.25s | +0.55s | +0.26s | 84~91 tok/s | 按 100 字批次透出 |

\* B 模式 Δ 含模型噪声：glm-5.3 强制思考使基线 TTFT 本身波动 12~20s（A/B 各有一轮推理耗尽 2048 tokens 只产出 2 个可见字）。**护栏的真实边际成本以单次 API 实测为准：输入检测 146~356ms（均值约 200ms）**。

模式 D 细节：每切片检测 130~246ms；TTFT 增量 ≈ 输入检测（~156ms) + 首切片积累（100字) + 首切片检测（~180ms)；200 字回答切 2~3 片，输出侧累计检测 318~492ms。

## 四、受影响指标清单与量级

| 指标 | 是否受影响 | 量级与说明 |
| --- | --- | --- |
| TTFT（首可见 token） | ✅ 受影响 | 输入检测 +0.2s；流式切片再 +0.3s 左右；全量缓冲则 TTFT=总耗时（+6s 起，随输出长度线性恶化） |
| 输出 token/s（模型生成） | ❌ 不受影响 | 护栏是下游旁路，各模式 83~103 tok/s 无差异 |
| 用户可见输出节奏 | ✅ 受影响 | 流式切片把逐 token 变成「每 N 字一批」，批次间隔 ≈ 切片积累时间 + 130~250ms 检测 |
| 总耗时（E2E） | ✅ 轻微 | 输入检测 +0.2s；切片检测累计 +0.3~0.5s（200 字回答）；全量缓冲 +0.2s（但体验差） |
| 吞吐/并发 | ⚠️ 间接受限 | 护栏单用户 QPS 上限 50/s；每请求消耗 1（输入）+N（切片）次配额，高并发网关需评估切片放大效应 |
| 输出 token/s（用户感知） | ⚠️ 口径注意 | 切片模式突发透出让「可见字符/s」表观值升高（318 vs 170 字/s），但首字更晚、节奏批量化，不代表模型变快 |

## 五、费用口径（实测 + 官方计费文档）

**自建网关 = API 接入：按成功调用次数计费，不按 token、不按文本长度。**

- 文本审核（内容合规维度）：**15 元/万次**；本账号提示词攻击维度默认开启，另计 15 元/万次 → 每次检测实际 0.003 元。敏感内容维度默认关闭，开启另计。
- 单次 ≤2000 字符同价；**流式每个切片是一次独立 API 调用、独立计费**（官方：成功请求 1 次 API 计 1 次费）。200 字回答切 3 片 → 输出侧 0.009 元/回答；滑动窗口切片（每 X 字送检最近 N 字）调用次数更多，费用更高。
- 非 200 错误请求不计费（本次 4 次 408 未产生费用）。
- hp 高性能版未在价格表单列，按文本高级类目计（以账单为准）。
- 对比：**百炼集成接入**才按 token 计费（基础 0.0004 元/千token、pro 0.003 元/千token，不足 1000 按 1000 计）——自建网关场景不适用。
- 用量对账：`GetCipStats` API 可查（当日数据 T+1 延迟，次日可查）。

**本次实测成本**：护栏 50 次 ≈ 0.15 元 + glm-5.3 16 次（24.7K completion tokens）< 0.2 元 ≈ **0.35 元**；加功能测试累计 **< 0.6 元**（预算 20 元）。

## 六、集成建议

1. 输入侧：同步检测（+0.2s TTFT 可接受），拦截注入/违规 prompt。
2. 输出侧：**hp 版 + 按字符切片（100~200 字/片）**，chatId+done 关联；避免全量缓冲（长文 TTFT 灾难）；谨慎用滑动窗口（费用放大）。
3. 网关与护栏同地域部署，走 VPC 内网接入点压低 RTT。
4. 高并发场景按「每请求 1+N 次调用」核算护栏 QPS（50/s）与费用。
5. glm-5.3 强制思考使 TTFT 基线达 12~20s，护栏增量占比 <5%；若客户用非推理模型（TTFT <1s），护栏 +0.2~0.5s 的相对占比会显著上升，需重新评估。

## 七、方法论与局限

- 每模式 4 次小样本，glm-5.3 推理长度波动大（含 2 轮截断异常值），TTFT 对比看趋势；护栏边际延迟以 50 次 API 直接测量为准。
- 测试环境为外网（办公网 → 北京），VPC 内网延迟会更低。
- 切片检测的「可见速度」为突发口径，非逐 token 口径。
